Section A & B

Problem Definition & System Objectives

⚠️ Traditional Theater Ticketing Flaws
  • Double-Booking Race Conditions: High-throughput ticket releases cause concurrent users to book identical seats.
  • Rigid Flat-Rate Pricing: Lack of dynamic pricing accommodating prime viewing angles, legroom, and luxury perks.
  • Tightly Coupled Checkouts: Hardcoding payment channels creates brittle monoliths that fail on payment expansion.
🎯 CineReserve Engineered Solutions
  • Atomic Invariant Protection: Strict state encapsulation in ShowtimeSeat.book() throwing SeatAlreadyBookedException on conflicts.
  • Polymorphic Tier Pricing: Dynamic calculation scaling prices across Standard (1.0x), Premium (1.35x), and VIP Recliners (1.80x + snack voucher).
  • Strategy Design Pattern: Decoupled, pluggable payment strategies (Card, UPI, Net Banking) resolved via factory.
OOP Pillar 1

Encapsulation & State Invariants

Domain models guard their internal state through private fields and domain operations rather than arbitrary setters. 

public void book(Booking booking) {
    if (this.status == SeatStatus.BOOKED) {
        throw new SeatAlreadyBookedException(
            "Seat " + seat.getSeatNumber() + " is already booked for this showtime!"
        );
    }
    this.status = SeatStatus.BOOKED;
    this.booking = booking;
}

public void recalculateTotals() {
    BigDecimal sum = bookedSeats.stream()
        .map(ShowtimeSeat::getEffectivePrice)
        .reduce(BigDecimal.ZERO, BigDecimal::add);
    this.subtotal = sum;
    this.convenienceFee = new BigDecimal("25.00").multiply(new BigDecimal(bookedSeats.size()));
    this.totalAmount = this.subtotal.add(this.convenienceFee);
}
OOP Pillar 2

Multi-Level Inheritance Hierarchies

Seat Hierarchy (JPA SINGLE_TABLE)

Abstract Seat inherits BaseEntity and defines core spatial coordinates.

  • StandardSeat: Baseline ergonomic theater seating.
  • PremiumSeat: Extra legroom (+8") & center-screen acoustic positioning.
  • VipReclinerSeat: 150° motorized leather recliners with snack vouchers.

User Hierarchy (JPA JOINED)

Base User entity extended into dedicated customer and administrative roles.

  • Customer: Adds loyalty reward points and membership tiers (SILVER, GOLD, PLATINUM).
  • TheaterAdmin: Adds staff employee badges and auditorium management rights.

Polymorphism & Dynamic Seat Pricing

Section A

Abstract

In contemporary agricultural commerce, smallholder producers typically capture only a fraction (30%–60%) of final retail prices due to multi-layered intermediate brokerage. Simultaneously, prolonged transit across fragmented wholesale supply chains results in substantial post-harvest food waste.

FarmDirect is an online shopping system engineered to bridge producers directly with end consumers. The system enforces two socio-economic guarantees:

90% Direct Farmer Payout (SDG 2.3) Every transaction guarantees 90% direct disbursement to the cultivator’s bank account, eliminating arbitrary broker commission cuts.
25% Freshness-Saver Discount (SDG 12.3) Perishable produce reaching its final 35% of shelf life automatically triggers a dynamic 25% clearance discount to accelerate consumption before spoilage.

Architected in compliance with OOP principles (Encapsulation, Inheritance, Polymorphism, Abstraction), the system is verified by unit and integration test suites.

Section C.1

Problem Definition: Problem Statement

The Middleman Squeeze

Small agricultural producers face 4 to 6 layers of intermediaries (village aggregators, commission agents, regional mandi operators, wholesale distributors, retail supermarkets). By the time produce reaches consumers:

  • Retail prices are inflated by 100%–200%.
  • Farmers receive as little as 30%–50% of the consumer rupee.
  • Farmers bear all production risks while middlemen capture guaranteed margins.

Agricultural Spoilage & Information Loss

Traditional distribution is plagued by prolonged cold storage bottlenecks and transit friction:

  • Substantial post-harvest spoilage occurs before produce reaches store shelves.
  • Consumers lack freshness visibility and consume stale produce.
  • Unsold perishable items near expiry are dumped rather than proactively discounted.

  • Usability: Fully responsive interface with accessible touch targets, color-coded badges, and clear feedback toasts.

Section F.1

Code Snippets: Encapsulation & Stock Guard

// In Product.java: Encapsulating inventory state and thread-safe stock reduction
@Entity
@Table(name = "products")
public abstract class Product extends BaseEntity {

    @Min(value = 0, message = "Stock quantity cannot be negative")
    private int stockQuantity;

    public synchronized void reduceStock(int quantity) {
        if (quantity <= 0) {
            throw new IllegalArgumentException("Quantity must be positive.");
        }
        if (this.stockQuantity < quantity) {
            throw new InsufficientStockException(
                "Insufficient stock for '" + this.name + 
                "'. Available: " + this.stockQuantity + ", Requested: " + quantity
            );
        }
        this.stockQuantity -= quantity;
    }
}

OOP Significance: Protects internal state invariants. No external caller can force inventory into negative deficit.

Section F.2

Code Snippets: Polymorphic Freshness Pricing

// In PerishableProduce.java: Dynamic 25% discount to halve food waste (SDG 12.3)
@Entity
@DiscriminatorValue("PERISHABLE")
public class PerishableProduce extends Product {

    @Override
    public boolean isClearanceDiscountApplied() {
        long remaining = getRemainingShelfLifeDays();
        // Triggers when 35% or less shelf life remains
        return remaining > 0 && remaining <= Math.ceil(shelfLifeDays * 0.35);
    }

    @Override
    public BigDecimal calculateEffectivePrice() {
        if (isClearanceDiscountApplied()) {
            return getBasePrice().multiply(new BigDecimal("0.75"))
                                 .setScale(2, RoundingMode.HALF_UP);
        }
        return getBasePrice().setScale(2, RoundingMode.HALF_UP);
    }
}

OOP Significance: Child classes implement their own pricing logic polymorphically without the cart or checkout service needing complex conditional type checking.

Section F.3

Code Snippets: Strategy Pattern (Payments)

// In PaymentStrategyFactory.java: Decoupled strategy resolution
@Component
public class PaymentStrategyFactory {
    private final Map<PaymentMethod, PaymentStrategy> strategyMap = new EnumMap<>(PaymentMethod.class);

    public PaymentStrategyFactory(List<PaymentStrategy> strategies) {
        for (PaymentStrategy strategy : strategies) {
            strategyMap.put(strategy.getSupportedMethod(), strategy);
        }
        strategyMap.put(PaymentMethod.DEBIT_CARD, strategyMap.get(PaymentMethod.CREDIT_CARD));
    }

    public PaymentStrategy getStrategy(PaymentMethod method) {
        PaymentStrategy strategy = strategyMap.get(method);
        if (strategy == null) throw new PaymentProcessingException("Unsupported method: " + method);
        return strategy;
    }
}

OOP Significance: Complies with the Open/Closed Principle. Adding a new payment mode requires only a new strategy class, leaving existing order code untouched.

Section F.4

Code Snippets: Service Abstraction & Remuneration

// In OrderServiceImpl.java: Orchestrating transactional checkout and direct farmer payout
@Override
public OrderResponse checkoutCart(CheckoutRequest request) {
    Cart cart = cartRepository.findByUserId(request.getUserId()).orElseThrow();

    // 1. Atomic inventory reduction
    for (CartItem item : cart.getItems()) {
        item.getProduct().reduceStock(item.getQuantity());
    }

    // 2. Polymorphic payment execution via strategy
    PaymentResult payment = paymentService.processOrderPayment(order, request.getPayment());

    // 3. UN SDG 2.3: Credit 90% direct payout to farmer entity
    for (OrderItem item : order.getItems()) {
        farmerRepository.findById(item.getFarmerId()).ifPresent(farmer -> {
            farmer.creditEarnings(item.getFarmerEarning()); // 90% direct payout
            farmerRepository.save(farmer);
        });
    }
    cart.clear();
    return OrderResponse.fromEntity(orderRepository.save(order));
}

OOP Significance: The Controller interacts exclusively with the OrderService abstraction, isolating web routing from persistence mechanics.
